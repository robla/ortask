* Overview

This document captures Gemini's architectural perspective and design roadmap for the =ortask= suite, reflecting the current multi-tool architecture (=ortask.py=, =projmgr.py=, =ortasklib/=, and the standalone =orglib/= package).

* The Core Design Principles ("The Ortask Way")

1. **Org-mode as Single Source of Truth**: No external database engines or sidecar metadata stores; the =.org= file is the authoritative database.
2. **Strict File Fidelity & Surgical Editing**: Edits are applied at the line level. Surrounding text, prose, property drawers, blank lines, and non-task sections must remain byte-exact. AST re-serialization is avoided for runtime mutations.
3. **Stable, Human-Readable IDs**: Numeric IDs (=t0001=, =t0001.1=) and week-based IDs (=tw26w24=) provide stable permalinks directly in headings.
4. **Zero-Dependency Runtime**: The core toolset depends strictly on the Python standard library, ensuring immediate portability and low startup latency.
5. **Clean Two-Layer Architecture**:
   - =ortask.py= (=ort=): Single task file manager operating on the =* Tasks= subtree.
   - =projmgr.py= (=pmgr=): Multi-project registry manager (=~/Projects=) and directory stack coordinator.

* CLI Refinement & Nomenclature

** The Problem with "doctor" (Prefer "check" or "audit")
The =projmgr doctor= verb feels overly cute and vague for a system administration and registry health tool.
- **Critique**: "Doctor" borrows from package managers (Homebrew, Flutter), but in a Unix task/project manager, users want direct, descriptive verbs.
- **Recommendation**: Rename or alias =doctor= to =check= (or =audit=). =pmgr check= accurately communicates what it does: validating symlink integrity, verifying task file discoverability, and reporting orphaned registry entries.

** Project & Task Inspection ("info" verbs)
Rather than overloading list commands, introduce dedicated inspection verbs:
- =pmgr info [PROJECT | PATH]=: Inspects registry state, project root, task file location, and private directory stacks. Supports scriptable flags (=--name=, =--path=, =--file=).
- =ort info=: Inspects the active Org task file, reporting heading ranges, ID allocation bounds, keyword state declarations, and task counts.

** Saving Directory Stacks (=cdproj -s= / =pmgr set-dirs=)
Shell directory stacks should be cleanly persistable:
- =cdproj -s [PROJECT]= forwards the live =dirs -l -p= stack to =pmgr set-dirs=.
- Auto-detects the current project from =$PWD= if omitted.
- Normalizes home paths to =~= and interactively prompts on directory subtractions (=remove=, =keep=, =cancel=).

* Interface & TUI Duality: ptui vs. cdproj

The project navigator (=ptui= / =projmgr.py -i=) and directory switcher (=cdproj=) share underlying project discovery but serve distinct workflows:

1. **Visual Distinction**:
   - =ptui=: Titled /Project Navigator/, labeled =PROJ=, showing open task counts. Focus is browsing and launching task managers.
   - =cdproj=: Titled /Change directory/, labeled =CD=, showing effective stack counts before aligned project paths; =*= marks a registry-defined custom stack.
2. **Directory Resolution & Precedence**:
   - When resolving stacks, the private list (=directories-private.org= in the registry) wins outright over shared task file =* Directories=, issuing stderr warnings for any omitted shared paths.

* External Libraries & Testing Strategy

1. **Runtime Isolation**: Keep runtime editing bespoke and stdlib-only.
2. **Testing Validation**: Use =orgparse= as an optional, zero-dependency test oracle (via =pytest.importorskip=) to verify that generated Org structures conform to standard Org syntax.
3. **Task State Keywords**: Standardize task headers with =#+TODO: TODO | DONE MOOT= across files to ensure third-party tools (Emacs, =orgparse=, =orgmunge=) parse terminal states consistently.
