#+TITLE: ortask — org-mode task CLI

=ortask.py= is a command-line tool for querying and editing TODO tasks
in org-mode files.  If a file has a =* Tasks= subtree, ortask uses that as the
task scope; otherwise it uses valid Org task headings throughout the file.
The CLI toggles TODO/DONE; shared workflow tools may use terminal MOOT.
SUPERSEDED remains a terminal compatibility alias for existing files.
Edits touch only selected task headings or explicitly inserted tasks.

Tasks use standard org-mode =TODO= / =DONE= keywords with stable IDs:

#+begin_example
,* Tasks
,** DONE t0001 Initialize LLMs in this directory
,*** DONE t0001.1 ChatGPT/codex
,*** DONE t0001.2 Gemini
,*** DONE t0001.3 Claude
,** TODO t0002 Build tool that updates this TODO list
#+end_example

* Quick start

#+begin_src sh
# list all tasks
./ortask.py list

# create an empty task file in the current directory
./ortask.py init

# list only open tasks
./ortask.py list --state todo

# show a single task with body and subtasks
./ortask.py show t0001

# add a task
./ortask.py add "Research FooCorp"

# add a subtask
./ortask.py add "Check Glassdoor reviews" --parent t0003

# archive all DONE task subtrees (or provide one task ID)
./ortask.py archive
./ortask.py archive t0002

# mark a task done
./ortask.py done t0002

# reopen a task
./ortask.py open t0002

# open the interactive task menu for the local task file
./ortask.py -i

# open the interactive project browser
./projmgr.py -i

# check for ID problems (dry run)
./ortask.py repair --dry-run

# fix ID problems
./ortask.py repair
#+end_src

By default, =ortask.py= walks upward from the current directory looking for
=tasks.org=, then =task.org=, then exactly one =*.task.org=, then compatibility names
such as =TODO.org= and =todo.org=. Use =--file= or the =ORTASK_FILE= env var to
override. Ambiguous matches stop with an error instead of guessing. If =ort add=
finds no task file, it creates =tasks.org= in the current directory.
=ort init= also creates =./tasks.org=, but without walking upward or adding a
first task; use =--file NAME.task.org= to choose another dedicated filename.

* Shell aliases and functions

For daily use, alias =ortask.py= as =ort= and =projmgr.py= as =pmgr=
(=misc/projmgr.aliases.sh= has the two =pmgr= lines):

#+begin_src sh
alias ort='/path/to/ortask.py'
alias pmgr='/path/to/projmgr.py'
alias ptui='pmgr -i'
#+end_src

Then: =ort list=, =ort add "Do the thing"=, =ort archive=, =ort done t0004=, =ort -i=,
and =pmgr -i=.

=cdproj= must be a shell function rather than an alias, because only the shell
can change its own directory stack:

#+begin_src sh
source /path/to/ortask/misc/cdproj.func.sh
#+end_src

* Bash completion

For command, option, and project-name completion, source the bundled completion
script — after =cdproj.func.sh=, though the order does not actually matter to
bash:

#+begin_src sh
source /path/to/ortask/misc/ortask-completion.bash
#+end_src

It registers completion for =ortask.py=, =./ortask.py=, =ort=, =projmgr.py=,
=./projmgr.py=, =pmgr=, =ptui=, and the =cdproj= shell function. After sourcing
it, typing =ortask.py ad<Tab>= or =ort ad<Tab>= completes to =add=, while
=pmgr -<Tab>= includes =-i= and =--interactive=. =cdproj <Tab>= and
=cdproj -s <Tab>= complete registered project names, as does =pmgr rm <Tab>=.
A Debian package can install the same file under
=/usr/share/bash-completion/completions/=.

* Requirements

Python 3.10+ (standard library only, no dependencies).
